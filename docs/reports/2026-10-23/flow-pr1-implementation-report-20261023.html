선택한 규칙이 다시 켜도 남도록

고정 확장자 선택과 커스텀 추가를 PostgreSQL에 저장하고, 새로고침·서버 재시작 후에도 같은 규칙을 유지하도록 구현했습니다.

PR #1 · 병합 완료최종 CI · 전체 통과분석 기준: PR 최종 구현 커밋

진행 과정 3줄

  1. 먼저 DB에 고정 확장자 7종을 모두 미선택으로 만들고, React 화면에서 서버에 저장된 값을 불러오게 했습니다.
  2. 사용자가 체크하거나 sh를 추가하면 Spring Boot가 입력·버전을 검사해 DB에 저장하고, 성공 응답을 받은 뒤 화면을 바꾸게 했습니다.
  3. 마지막으로 새로고침과 실제 서버 재시작을 실행해 값이 남는지 확인하고, 오류·모바일 동작까지 CI에서 시험했습니다.

범위: T01~T04. 소스 링크는 커밋 7e0ec56389e5cfa740fa3153dbfcb62af08208c8에 고정했습니다. 읽는 순서: 흐름 → 클릭형 소스 → 시험 결과.

검사 통과

DB 변경과 버전 증가를 함께 저장 → 성공 응답 → 화면 체크·태그·개수 확정

검사 실패 또는 저장 결과 불확실

오류 안내·입력 보존. 충돌·불확실한 결과는 수정 잠금 → 최신 규칙 다시 조회. 단순 입력 오류는 수정 후 재입력.

관련 소스 연결

오른쪽 번호를 누르면 왼쪽 설명과 코드가 바뀝니다. Tab으로 이동해 Enter·Space로 선택할 수도 있습니다.

실선: 주요 호출·오류 응답 / 점선: 시험 검증. 정상 응답은 호출의 역순으로 화면까지 돌아갑니다. V1은 최초 DB 생성 때 적용됩니다.
