# 구현 요청과 진행 기록

## DEC 검증·보안 후속 구현 — 2026-10-23

사용자 요청: “기획 /개발 고려사항에서 3-1 검증/보안관점 DEC에서 권장초안에 적힌 대로 참고하여 과제를 진행합니다. 이후 PR까지 진행해주세요.”

가이드의 DEC-01~13을 대조해 02~11을 구현 기준으로 채택했다. 단일 정책·고정 버전 구성은 유지하며 공개 권한·격리와 보관 기간·전체 총량은 숫자·방식이 없어 공개 전 결정 항목으로 남겼다. 원격 main 및 열린 PR을 확인한 뒤 feat/dec-upload-validation 브랜치와 PR #2를 만들었다.

업로드·커스텀 삭제·파일 저장·메타데이터·같은 출처 브라우저 요청 검사를 추가했다. 기존 T01~T04 회귀 외에 실제 PostgreSQL·파일·HTTP 크기 경계, 경합, 장애 주입과 브라우저 시험을 구성했다. 초기 로컬 Node API 6개 통과. CI 결과는 TEST_RESULTS와 PR에 기록한다. 실제 악성코드나 개인 파일은 시험에 사용하지 않는다.

실제 시험에서 크기 초과 응답의 연결 끊김을 발견해 Tomcat의 중단 요청 소비 한도를 12 MiB로 맞췄다. 브라우저 경로에서는 Vite의 문자열 프록시가 Host를 바꾸는 동작을 발견해 changeOrigin=false를 명시했다. 보안 검사를 끄거나 실패 검사를 삭제하지 않았다. 서버 24개·Node 6개·재시작·브라우저 5개를 최종 커밋에서 다시 확인한다. 오류 requestId·캐시 제어와 트랜잭션 오류 분류도 맞췄다. 최종 결과는 PR #2의 실행 링크로 남긴다.

## 2026-10-23

사용자 요청: 가이드와 리서치에 따라 **T01~T04: 최초 상태 → 선택 저장 → 재시작 유지 → 커스텀 추가**를 구현하고 최소 시험 시나리오를 구현한 후 GitHub PR을 생성한다.

확정 스택: Spring Boot, React, PostgreSQL, Docker, Git. 저장소: `feed-mina/flow_fileupload_AI`.

진행:

1. 기존 가이드·UI 리서치와 문서만 있던 main 상태를 확인했다.
2. `feat/policy-t01-t04` 브랜치에서 정책 DB·Flyway·API와 Ant Design React 화면을 추가했다.
3. 저장 응답 후 상태 확정, 실패 시 입력 유지, 불확실한 저장 결과의 재조회, 버전 충돌 방지를 구현했다.
4. 로컬 Node API 시험 4개가 통과했다. Docker 엔진·npm 네트워크 제한을 확인하여 실제 DB·브라우저 검증은 GitHub Actions에서 실행하도록 구성했다.
5. 재시작 시험에는 exe=false뿐 아니라 scr=true와 동일 버전·행 ID 보존 검증을 포함했다.
6. Actions #2에서 서버 통합 6개, Node API 4개, 실제 재시작 T01~T04, 브라우저 4개, 프론트 빌드와 Docker 구성 검사가 모두 통과했다. 의존성 잠금파일을 추가하고 `npm ci`를 사용하도록 고정했다.
7. 가이드에 실제 구현 파일과 PR 링크를 추가했다. 실제 Compose 이미지 빌드·기동은 실행하지 않았다고 기록했다.

입력 정규화·중복·동시성 등 세부 정책은 임시안으로 기록했다. 최소 시험 통과 자체를 모든 DEC의 확정으로 취급하지 않는다. 전체 대화 로그는 별도의 기존 대화 로그 파일에 계속 기록한다.
